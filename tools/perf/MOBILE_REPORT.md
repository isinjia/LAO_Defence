# 모바일 최적화 보고서

계측 환경: 로컬 서버(`tools/serve.py`)에서 Chromium 모바일 에뮬레이션(375×812, DPR 2, coarse pointer)으로 측정했습니다.
프레임 비용은 `GAME.prof(n)`의 단계별 평균(ms)이며, 데스크톱 CPU에서 잰 값입니다.
표준 부하는 유닛 54기(필드 18칸 × 3)와 무적 적 100기입니다.

## 전후 비교

| 항목 | 이전 | 이후 |
|---|---|---|
| 프레임 비용(표준 부하) | 31.5 ms (bench) | 애니메이션 3.2 + 렌더 1.9 + 로직 < 0.1 ≈ **5.2 ms** |
| 드로우콜(표준 부하) | 674 (+ 파티클당 1콜, 최대 900) | **278** (파티클·투사체·그림자·HP바·링은 블렌드/순서별 1콜) |
| SD 정점 처리 | CPU 스키닝 + 프레임마다 정점 5종 업로드 | **GPU 스키닝**(뼈 슬롯 float 텍스처만 업로드), 색/UV는 변경 시에만 |
| SD 아틀라스 GPU 메모리(49리그) | 약 422 MB (밉맵 별도) | 데스크톱 ×0.25(≈105 MB), 모바일 ×0.12(≈52 MB) |
| 첫 화면까지 다운로드(모바일) | 10.8 MB | **7.2 MB** (준비 완료 약 3.1초, 로컬) |
| SD 데이터 전체 | 42 MB | **33 MB** (클립 트랙 uint16 양자화, 본 일치도 99.98 유지) |
| 효과음 | 18 MB WAV | **1.8 MB** MP3 (모노 96k) |
| UI 에셋 | 2.14 MB (스프라이트 JS/CSS 중복, PNG) | **0.84 MB** (CSS 1회, 무손실 WebP) |
| 백그라운드 선로딩 | 49리그 전부(42 MB) | 모바일은 B·A급 유닛과 다음 웨이브 적만 받음. 나머지는 필요할 때 로드하고 GPU에 미리 올림 |

## 적용 기법

- **렌더**
  - 화질은 높음·중간·낮음 3단계(DPR 2/1.5/1, 블룸 1/0.5/끔)입니다. 모바일은 '중간'에 MSAA 끔으로 시작합니다.
  - 자동 모드는 90프레임 평균이 22 ms를 2회 넘으면 한 단계 낮추고, 최저 단계에서는 30fps로 고정합니다. 다시 올리지는 않아 진동하지 않습니다.
  - 블룸을 끄면 컴포저 없이 직접 렌더합니다.
  - 타이틀·로딩 화면이 필드를 가리는 동안은 렌더하지 않고, 일시정지 중에는 10프레임에 1회만 렌더합니다.
- **CPU**
  - GPU 스키닝: `js/sd.js`의 `SD.gpuSkin`, `sdShader`.
  - 애니메이션 LOD: 적이 많으면 적은 격프레임으로 갱신합니다. 모바일에서 필드가 붐비면 유닛도 격프레임으로 갱신하며, 각자 누적 시간으로 따라잡습니다.
  - 파티클은 하나의 아틀라스와 인스턴스 배치로 그리고, 생성 시 `needsUpdate`를 제거했습니다.
  - 원작 이펙트(fxbake)는 인스턴스를 풀링하고 동시 개수에 상한을 둡니다(모바일 36). 상한을 넘으면 가벼운 파티클로 대체합니다.
- **메모리**
  - 아틀라스는 화면 해상도에 맞춰 축소해 업로드합니다(간격 패딩으로 번짐 방지).
  - SD 데이터는 로드 후 base64 텍스처 문자열과 데이터 `<script>`를 해제합니다.
  - 파티클 예산은 모바일 450개입니다. 데미지 숫자 DOM 풀은 모바일 36개입니다.
- **네트워크**
  - 효과음은 MP3로 바꿨습니다.
  - UI 에셋 중복을 제거하고 WebP로 바꿨습니다.
  - SD 클립은 uint16으로 양자화했습니다.
  - 다음 웨이브의 적만 미리 받습니다.
  - 서비스 워커를 둡니다. 대용량 데이터는 캐시 우선, 코드는 백그라운드에서 재검증합니다.
- **오디오**
  - http(s)에서는 Web Audio로 재생합니다(디코드 1회, 저지연, 동시 재생 12개 상한). file://에서는 HTMLAudio로 폴백합니다.
  - 첫 터치·키 입력에서 오디오를 언락합니다(iOS 대응).
  - 백그라운드로 가면 음악과 효과음 컨텍스트를 정지합니다.
- **배터리·수명주기**
  - 탭이나 앱이 숨겨지면 자동으로 일시정지합니다(rAF도 멈춤).
  - 30fps 제한 옵션이 있습니다.
  - WebGL 컨텍스트를 잃으면 안내 후 다시 로드합니다.
- **입력**
  - 포인터 이벤트로 처리하고, `pointercancel`이 오면 드래그를 복구합니다.
  - 터치 후 hover 하이라이트를 해제합니다.
  - 셀 터치 영역은 약 80px입니다.
  - 위치 교환 시 진동합니다(옵션).
  - `touch-action: none`, 탭 하이라이트·콜아웃 제거, `(hover: none)`에서 hover 스타일을 무효화합니다.
- **레이아웃**
  - 세로(필드 3×6)를 지원합니다.
  - 짧은 가로 화면(높이 520px 이하)에서는 상단 HUD를 압축하고 행동 버튼을 우측 레일에 둡니다. 필드가 662×327로 이전보다 63% 높습니다.
  - 노치·홈 인디케이터는 `env(safe-area-inset-*)`로 처리합니다.
  - 모바일에서 유닛 상세는 바텀시트로 열고, 결과 화면은 불투명하게 처리합니다.
- **PWA**
  - manifest(fullscreen), 아이콘 192/512/180, theme-color, apple-mobile-web-app 메타를 넣었습니다.
  - 설정에 전체 화면 토글을 두었습니다.
- **설정 저장**
  - 그래픽 품질(자동/높음/중간/낮음), 프레임 제한, 볼륨, 음소거, 데미지 숫자, 화면 흔들림, 진동을 localStorage에 저장합니다.

## 검증

- GPU 스키닝 결과는 CPU 결과와 외형 점수가 같습니다(`sdvisual.html?gpu=1`, 8개 리그 72포즈 평균 94.90 = 94.90).
- 클립 양자화 후 본 일치도는 `sdcompare.html`에서 OVERALL 99.98, 최저 리그 99.81로 변화가 없습니다.
- 자동 플레이 시뮬레이션 11웨이브(보스 포함)와 실시간 플레이에서 콘솔 오류가 없었습니다.

## 2차 반영 (리뷰 68점 이후)

| 지적 | 조치 |
|---|---|
| fxbake 데이터 과대 (티타니아 22.8MB, 파싱 665ms) | 프레임을 바이너리(int16 위치·uint16 UV/인덱스·uint8 색, base64)로 바꾸고 GPU 정규화 속성으로 바로 씀. 1.5MB 초과 이펙트는 15fps로 굽기. 전체 59MB → **25MB**(티타니아 5.3MB). 모바일은 1.2MB 초과 이펙트(5종)를 로드하지 않고 파티클로 대체(`FX_META.size`). 원작 일치도 전체 94.30 / 투사체 95.05 유지(fxcompare) |
| 서비스 워커 결함 | `tools/stamp_build.py`가 배포 파일 해시로 `BUILD` 각인, 활성화 시 이전 캐시 삭제. localhost·127.x·사설 IP·::1 제외. 200 응답만 저장(Range/opaque 제외), put 실패 처리, CDN 스크립트 `crossorigin="anonymous"` |
| fxbake 아틀라스 원본 해상도·업로드 히치 | `FXB.texScale`(모바일 0.5), 4096 상한, 밉맵 끔, prepare 시 `renderer.initTexture` |

| DOM 리플로우 | 데미지 숫자는 span 재사용 + Web Animations(transform/opacity), offsetWidth·innerHTML 제거. 게이지는 `scaleX`(값 양자화로 변경 시에만 쓰기). 팝업은 렌더 시 1회 측정, 프레임마다 transform만. `#numLayer contain: strict` |

| 적 SD 인스턴스 미풀링 | `SD.acquire/release` 리그별 풀(최대 48) |
| 리본 지오메트리 재생성 | 위치 버퍼를 제자리에서 갱신 |
| 오디오(iOS) | BGM을 MediaElementSource와 GainNode로 연결(iOS 볼륨 무시 대응), `interrupted` 상태 복구, 자주 쓰는 17종만 선디코딩 |
| 기타 | 일시정지 중 1회만 렌더, 모바일 `powerPreference: default`, 컨텍스트 손실 시 일시정지하고 `webglcontextrestored` 후 이어하기, 미사용 WAV 18MB를 `tools/_unused_sfx_wav/`로 이동, 모든 스크립트 `defer` 및 CDN preconnect(로딩 화면이 먼저 그려짐) |

갱신된 수치: 부하 프레임 애니메이션 2.44 + 렌더 1.64 ≈ **4.3 ms**, 드로우콜 279, 힙 102MB, 초기 다운로드 약 6.0MB.

## 3차 반영 (리뷰 81점 이후)

| 지적 | 조치 |
|---|---|
| SD 풀 무한 보관 | 리그당 24·전체 40 상한, 웨이브 전환 시 이전·현재·다음 웨이브 리그 외 풀 dispose(`SD.trimPool`). 모바일은 끝난 웨이브의 적 리그를 템플릿·아틀라스·원본 데이터까지 해제(`SD.evict`, 필드·시체에서 쓰는 리그 제외, 다시 필요하면 재로드). fxbake 풀도 웨이브마다 이펙트당 4개로 축소 |
| 전투 중 리그 빌드 히치 | 리그 아틀라스를 빌드 단계에서 미리 패킹(WebP 1장, 데스크톱 표시 배율 0.5로 저장, 간격 6px). 런타임은 `img.decode()`(백그라운드 탭 대비 onload 폴백) 후 텍스처 생성만 하고, 모바일은 한 번만 축소. 단계 사이에 `requestIdleCallback`(타이머 폴백)로 양보. **리그 4개(라미엘·철의 왕자·골타리온·헬라) 로드 중 50ms 초과 long task 0건**(데스크톱). SD 데이터 33MB → **24MB** |
| 데미지 숫자 cssText | 숫자 시트는 루트 CSS 변수(`--dmg`, `--dmgc`)로 1회 설정하고 클래스로 참조. 자리마다 width·height·margin·background-position만 갱신. `ultCallout`도 WAAPI transform으로 변경 |
| BGM 누수 | 엘리먼트 1개 + MediaElementSource 1개를 세션 내내 재사용하고 src만 교체 |
| SW 세션 중 버전 혼합 | 기존 컨트롤러가 있던 상태에서 `controllerchange`가 오면 전투 중이 아닐 때 리로드(전투 중이면 끝난 뒤). 모든 `build_*.py`가 끝날 때 `stamp_build`를 자동 호출하고, 모든 파일을 전체 내용으로 해시 |
| 인스턴스별 뼈 텍스처 | 모든 GPU 스키닝 리그가 공유 뼈 아틀라스(행 블록 할당·해제·병합, 필요 시 2배 확장)를 쓰고, 첫 SD 메시 `onBeforeRender`에서 프레임당 1회 업로드. 외형 점수 GPU = CPU(94.90) 유지 |
| 모바일 기본 블룸 | 모바일 '중간' 품질은 블룸 없음(DPR 1.5) |

검증:
- 자동 플레이 48웨이브(보스 4회)를 돌렸고 오류는 없었습니다.
- 모바일 리그 수는 유닛 위주로 최대 약 41개입니다(적은 웨이브 종료 후 해제).
- 힙은 웨이브 17~47 동안 118MB에서 182MB로 올랐습니다. 당시에는 GC 시점 때문인지 실제 누적인지 확인하지 못했고, 4차에서 해결했습니다.
- 외형 점수(441포즈, GPU)는 95.35입니다. 도구가 512px로 렌더하므로 0.5배 아틀라스의 해상도 차이가 반영된 값이고, 게임 내 데스크톱 표시 배율은 이전과 같습니다. 배율 1로 빌드하면 레기온이 97.1로 돌아옵니다.

## 4차 반영 (리뷰 87점 이후)

| 지적 | 조치 |
|---|---|
| 1. 업데이트 리로드가 결과 화면을 지움 | 리로드는 `phase === 'title'`에서만 합니다. 전투·결과 화면에서는 새 SW가 대기만 합니다 |
| 2. 세션 중 버전 혼합 | `sw.js`에서 `skipWaiting`/`clients.claim`을 제거했습니다. 새 SW는 `waiting` 상태로 머물고, 그동안 옛 SW와 옛 캐시가 세션 끝까지 응답합니다. 타이틀 화면에서만 페이지가 `postMessage('skipWaiting')`을 보내고, 이어지는 `controllerchange`에서 리로드합니다 |
| 4. 모바일 런타임 축소·NPOT 밉맵 | 리그 아틀라스를 표시 배율별 파일로 분리했습니다: `js/sd/<id>.a50.js`(데스크톱 0.5), `<id>.a35.js`(모바일 0.35). 데이터 스크립트와 병렬로 로드하고, 모바일은 717px 이미지를 그대로 업로드해 캔버스 축소가 없습니다. WebGL1에서는 밉맵을 끕니다(`SD.mipmaps = isWebGL2`) |
| 5. 뼈 아틀라스 2배 확장 | 필요한 만큼(최소 32행)만 늘립니다 |
| 6. evict 시 GPU 버퍼 | 정적 속성(lp/si/sw), 템플릿 인덱스, `idxCache` 인덱스를 임시 지오메트리에 붙여 `dispose()`합니다 |
| 7. 프레임당 UI 할당 | odds HTML은 luck이 바뀔 때만 다시 만들고, 조합 가능 수는 250ms마다 계산합니다. 배지는 엘리먼트를 캐시하고 개수가 바뀔 때만 갱신합니다 |

검증:
- **SW 업데이트(실제 브라우저, `?sw=1`)**
  - 전투 중과 결과 화면에서는 `waiting=true` 상태로 리로드가 없었습니다.
  - 타이틀로 돌아가자 리로드되었고, 이전 캐시가 정리되었습니다.
- **모바일 375×812 에뮬레이션, 50웨이브 자동 플레이**
  - 리그 수: 웨이브 15 이후 27~28개에서 유지
  - 힙: 웨이브 20~50 동안 138~152MB에서 유지(3차의 118~182MB 상승 추세 해소)
  - 오류: 0건
  - a35 파일만 요청했고 a50 요청은 0건이었습니다. 텍스처 소스는 `HTMLImageElement`로, 캔버스를 거치지 않습니다.
- **데스크톱**: 유닛 14기 소환·리그 45개 로드 중 50ms 초과 long task 0건, 렌더링 정상
- **다운로드 크기**
  - 리그 데이터 17MB, 아틀라스 a50 7.2MB, a35 4.6MB
  - 모바일 리그 다운로드는 24MB에서 약 21.6MB로 줄었습니다.

실기기(iPhone SE·360×800·노치 가로) 측정은 이 환경에서 불가능합니다.

## 5차 반영 (리뷰 90점 이후)

| 지적 | 조치 |
|---|---|
| 1. evict GPU 해제 무효 | `gpuRelease()`: 공유 정점 속성(lp/si/sw)·템플릿 인덱스·`idxCache` 인덱스를 임시 지오메트리에 붙이고, draw range 0으로 한 번 그려 `WebGLGeometries`에 등록한 뒤 `dispose()`합니다. `SD.renderer`는 게임이 지정합니다. **실측: evict 1회에 `gl.deleteBuffer` 4회**(인스턴스 dispose 4회와 별도) |
| 2. 대기 중 옛 캐시 오염 | 빌드 단위로 불변 캐시를 씁니다. **모든 요청이 cache-first**이고 SWR(백그라운드 갱신)을 제거했습니다. `stamp_build`가 코드·UI 목록(`CORE`, 16개)을 `sw.js`에 각인하고, install 때 `cache:'reload'`로 HTTP 캐시를 우회해 미리 받습니다. 캐시에 없는 요청(지연 로드 데이터)은 `cache:'no-cache'`로 받습니다 |
| 3. 아틀라스 실패 복구 | 아틀라스 스크립트 누락이나 디코드 실패 시 `null`을 돌려주고 `pending`을 지워 다음 `prepare()`에서 재시도합니다(데이터는 유지하고 아틀라스만 다시 받음). **실측: a35 스크립트를 1회 강제로 실패시켰을 때 첫 시도 null, 재시도에서 정상 로드(717px)** |
| 4. 파티클 GC와 O(n) | 파티클 객체 풀(최대 600)을 둡니다. 삭제는 프레임당 1회 제자리 압축으로 처리해 그리기 순서를 유지하고, `findIndex`/`indexOf`/`splice`를 제거했습니다. 예산 초과 시 회수는 커서로 처리합니다. kill된 스프라이트는 소유자가 참조를 쥐고 있을 수 있어 풀에 넣지 않습니다. `G.enemies`도 제자리에서 압축합니다 |
| 5. 레이아웃 | `visualViewport` resize와 `orientationchange`(2프레임 뒤 resize)를 연결했습니다. 크기별 수정은 아래 목록과 같습니다 |

## 8차 반영: base64 → 바이너리 (리뷰어가 코드로 남은 유일한 항목으로 지목)

- **http(s) 경로**
  - 리그 아틀라스는 `js/sd/<id>.a35.webp`/`.a50.webp` 원본 WebP를 `<img>`로 바로 받습니다.
  - 이펙트는 `js/fx/<name>.m.js`(메타데이터만) + `<name>.webp`(아틀라스) + `<name>.bin`을 받습니다. `.bin`은 int16/uint16/uint16/uint8 순으로 2바이트 정렬했고, `fetch().arrayBuffer()`의 TypedArray 뷰를 복사 없이 GPU 업로드 소스로 씁니다.
  - base64 디코드 루프(`atob` + 바이트 복사)와 대용량 문자열 파싱이 없어졌습니다.
- **file:// 경로**: WebGL이 file:// 이미지를 cross-origin으로 거부하므로, 기존 자립형 스크립트를 그대로 씁니다. 원래 요구사항이 file:// 실행 유지입니다.
- **빌드**: `tools/binfiles.py`를 추가했고, `build_sd.py`와 `build_fx.py`가 두 형식을 함께 출력합니다.
- **실패 처리**: `.bin`이나 `.webp`를 받지 못하면 `null`을 돌려주고 `pending`을 지워, 다음 웨이브에 재시도합니다.

측정:
- **전송량**
  - 모바일 리그 아틀라스: 4.6MB에서 3.4MB(-26%)
  - 이펙트: 25MB에서 18.6MB(-25%)
  - base64 스크립트 37.2MB 전체가 27.9MB로 줄었습니다.
- **정확도**: http 경로의 이펙트 비교 점수가 **94.30**으로, 이전 base64 경로와 같습니다. 바이너리 디코딩은 무손실입니다.
- **모바일 375×812 자동 플레이 30웨이브**: 오류 0건, 리그·이펙트 정상 로드. 이 실행에서 `a35.js` 요청은 0건이었고 webp·bin·m.js 요청만 발생했습니다.
- **file://**: 이 환경의 브라우저 창이 file:// 페이지를 실행하지 않아 실측하지 못했습니다. 코드 경로는 이전 회차와 같습니다.
